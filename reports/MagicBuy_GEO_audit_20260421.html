1.3　核心問題 Top 5

#1 結構性缺失
FAIL 全站 Schema 標記為零。經 JavaScript 實測 document.querySelectorAll('script[type="application/ld+json"]') 回傳 0 個節點，Otterly.AI 同步驗證 Schema.org structured data 評分為 0/25。Organization、WebSite、FAQPage、Service 等核心 Schema 全部缺席——這是 AI 引擎識別品牌實體與內容結構的主要信號源。
#2 社交分享層
FAIL Open Graph 標籤完全未部署（Otterly：0/15）。實測整個頁面僅有 viewport 與 description 兩項 meta，缺少 og:title、og:image、og:description、og:type。這意味著當 LINE、Facebook、Slack、Threads 等平台分享連結時，無法產生品牌縮圖卡片——對 B2B 採購這種「決策週期長、需多方分享評估」的場景特別致命。
#3 主動引導信號
WARN llms.txt 與 sitemap.xml 缺失。經 Otterly.AI 雙工具驗證，伺服器層級 robots.txt 對 GPTBot / ClaudeBot / PerplexityBot / Google-Extended 等 20+ 種 AI 爬蟲均為 Allow（被動允許），因此「可被爬取」這個基本門檻是通過的。但缺乏主動引導信號——無 llms.txt（提供 AI 友善的網站地圖）、無 sitemap.xml（指引爬取優先序），AI 引擎只能盲爬，無法理解網站重點。
#4 託管架構
WARN 使用 GitHub Pages 子路徑託管，非自有網域。實際網址為 anchennie.github.io/magaicbuy_website4/，而非業務網域 magicbuy.com.tw。此架構下：(1) 網域權威無法累積到品牌名下；(2) AI 搜尋引擎對 github.io 子路徑的信任權重低於獨立網域；(3) 品牌一致性受損（用戶看到 anchennie 個人帳號會質疑可信度）。
#5 內容深度
WARN 單頁式網站、內容深度不足。Otterly.AI 評分 Content variety 僅 20/40、Rich content elements 36/60，與本健檢「無 Pillar-Cluster 架構」的判定一致。全站約 3,000 字，僅一個頁面承載所有資訊，無部落格、無服務詳情頁、無 About 頁。此外 Otterly 額外指出 Specificity 45%、Acronyms 50%——多項術語（ERP、API、CFS、CY、PLUS、1688）未定義，對非電商背景者形成理解門檻。
