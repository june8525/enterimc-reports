1.3　核心問題 Top 5

#1 結構性缺失
FAIL 全站 Schema 標記為零。經 JavaScript 實測 document.querySelectorAll('script[type="application/ld+json"]')，回傳 0 個節點，意味著 Organization、WebSite、FAQPage、Product 等核心 Schema 全部缺席。這是 AI 引擎識別品牌實體與內容結構的主要信號源——零 Schema 等於告訴 AI「本站缺乏可結構化擷取的資訊」。
#2 技術檔案
FAIL llms.txt 與 robots.txt 均為 404。實測 /llms.txt 與 /robots.txt 皆回傳 GitHub Pages 404 頁面。AI 爬蟲如 GPTBot、ClaudeBot、PerplexityBot 無法透過 robots.txt 取得爬取許可信號，新興的 llms.txt 標準（提供 AI 友善的網站地圖）完全未部署。
#3 託管架構
FAIL 使用 GitHub Pages 子路徑託管，非自有網域。實際網址為 anchennie.github.io/magaicbuy_website4/，而非業務網域 magicbuy.com.tw。此架構下：(1) 網域權威無法累積到品牌名下；(2) robots.txt / sitemap.xml 只能由 anchennie.github.io 根目錄控制；(3) AI 搜尋引擎對 github.io 子路徑的信任權重低於獨立網域。
#4 內容深度
WARN 單頁式網站、內容深度不足。全站約 3,000 字，僅一個頁面承載所有資訊，無部落格、無服務詳情頁、無 About 頁、無個別產品頁。主題叢集（Pillar-Cluster）架構完全不存在，AI 引擎無法判定本站在任何特定主題領域的權威性。
#5 E-E-A-T
WARN 內容無作者署名、無發文日期、無引用來源。雖然有 7 則 FAQ 與 8+ 則客戶見證（含日期 2025年12月28日、3月13日等），但服務說明文字無任何作者節點、無 Person Schema、無 dateModified 時間戳。在 YMYL 相鄰領域（金流、跨境貿易涉及外匯申報），這是 AI 引擎評估可信度的關鍵缺口。

檢查項目結果實測說明
HTTPS 加密 PASS GitHub Pages 預設提供有效 HTTPS 憑證，此項通過。
RWD 響應式設計 PASS 含 viewport meta（width=device-width, initial-scale=1.0），具備響應式設計基礎。

Canonical URL WARN 實測 link[rel="canonical"] 為 undefined（未設定）。當未來內容被複製至其他網域時，無標準連結信號供 AI 引擎判定原始出處。

立即修復建議（第一層）

  • ①【最高優先】將網站遷移至自有網域 magicbuy.com.tw。GitHub Pages 子路徑架構是所有技術問題的結構根源，不遷移則後續修復均為臨時性。遷移後可使用 Cloudflare Pages、Vercel、自管 Nginx 等方案。
  • ②遷移完成後立即建立 /robots.txt，明確允許 GPTBot、ClaudeBot、Google-Extended、PerplexityBot、Bytespider（字節系如 Doubao）等主流 AI 爬蟲。

  • ⑤若未來擴充為多頁架構（部落格、服務詳情頁等），同步部署 sitemap.xml 與 IndexNow 協議，對 Bing Copilot 與 ChatGPT Search 引用率有直接助益。
